## Сквозной проект: Polymer CRM / PTMS

Система управления продажами полимерного сырья: клиенты, товары/марки, заявки, заказы, складские остатки, пользователи/роли, отчётность.

- **V1 — Java Core:** консольные операции и хранение данных в коллекциях.
- **V2 — PostgreSQL:** схема БД, SQL, сохранение данных.
- **V3 — Spring Boot:** REST API и слои controller/service/repository.
- **V4 — Production-подход:** безопасность, валидация, тестирование, логирование, Docker, документация.

## Формат обучения

Теория → короткий пример → самостоятельная задача → code review → закрепление.
Одна практическая задача за раз; готовое решение — только после попытки или по прямой просьбе. Темы считаются освоенными по практике, а не по прочтению. Регулярное повторение и мини-собеседования.

### Еженедельная проверка знаний — воскресенье

Каждое воскресенье проводим проверку понимания пройденного материала, преимущественно без изучения новых тем. Продолжительность — ориентировочно 45–60 минут:

- 10 минут — теория, объяснение своими словами;
- 10 минут — анализ кода и поиск ошибок;
- 20–30 минут — самостоятельная практическая задача по PTMS;
- 10 минут — разбор решений и пробелов.

Ориентир оценки: теория 30%, анализ кода 20%, практика 50%. Условные уровни: 85–100% — уверенное понимание, 70–84% — отдельные пробелы, ниже 70% — дополнительная практика. Итоговая оценка не означает автоматического освоения: проверяем сохранение знаний в последующие недели. Вопросы включают материал прошедшей недели и темы предыдущих занятий. После проверки записываем балл, ошибки, рекомендации и время в учебный журнал. Первый тест запланирован на воскресенье 01.11.2026 (по инициативе ученика; запускается при обращении в чат).


## Методика CLEAR и критерии освоения

Используем **CLEAR Learning Cycle** (Connect, Launch, Explore, Assess & Adjust, Reflect & Reinforce) как структуру урока, а не балльную научно валидированную шкалу.

1. **Connect:** коротко вспомнить проверенную предыдущую тему и зависимости.
2. **Launch:** одна измеримая цель урока и объяснение, зачем это нужно для PTMS/backend.
3. **Explore:** объяснение → короткий пример → самостоятельная задача (одна за раз).
4. **Assess & Adjust:** code review (корректность, граничные случаи, читаемость, архитектура); исправления самим учеником; не считать код запущенным без запуска.
5. **Reflect & Reinforce:** итог, повторные вопросы через 1–3 занятия и воскресный контроль.

**Статусы конкретных навыков:** 🟡 теория разобрана; 🔵 самостоятельная практика принята; 🟢 подтверждено повторной проверкой/комбинированной задачей. Прочитанная теория не равна освоению. Если на теме обнаружен пробел, сначала закрыть его, затем перейти далее.
